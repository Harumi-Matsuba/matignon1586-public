# 方法と検証

[English](METHOD.en.md)

## 手順
1. **画像**：Gallica の BnF fr. 15572（ark:/12148/btv1b9061879d）の225コマ（f. 218r）と226コマ（f. 218v–219r）。ページごとに傾きを補正し（f. 218r −3.5度、f. 218v −0.7度、f. 219r −2.6度）、行ごとに3つに分けて拡大した。画像はこのリポジトリに含めていない。
2. **書き起こし**：記号に名前を付け（`data/key.tsv` の1列目）、行ごとに記号名を並べた（`data/transcription_*.txt`）。原本の縦線（語の区切り）は `|` で残した。形に自信のない記号には `?` を付けた。
3. **鍵**：友清理士氏（Cryptiana）が復元した Mayenne–Forget の Cipher-2 の表を使った。表にない記号は、この書簡の中で複数の語に当てはまる値を探して補い、`inferred` として区別した。根拠の語は `data/key.tsv` の4列目にある。
4. **解読**：`src/decode.py` で鍵を書き起こしに当てた（`data/decoded_*.txt`）。読み（[READING.md](READING.md)）は、その出力に、語の区切りと句読点を補ったもの。

## 較正（当時の解読がある書簡での測定、2026-10-20）
- 対象：BnF fr. 15573 f. 103v（Mayenne から国王へ、1586年9月、同じ Cipher-2。Gallica ark:/12148/btv1b90618780 の212コマ）。左余白に当時の解読がある。
- 手順：暗号の1〜6行目（記号157個）を、当時の解読を見る前に、この書簡と同じ記号名・同じ鍵で書き起こした（`calib/transcription_f103v_l1-6.txt`）。左端に余白の解読の切れ端が写っていたが、読まないようにした。その後で、当時の解読（Brett Burford 氏の目読みによる文字を、212コマの画像で確かめたもの。« lad[icte] riviere » の略記だけ直した。`calib/ref_f103v_l1-6.txt`）と、文字の単位で突き合わせた（`src/calib.py`）。
- 結果：参照214文字に対し、編集距離54（置換21、脱落24、余分9）。**文字の一致率74.8%**（表の記号だけで71.0%）。
- 違いの中身（目で分類したもの）：
  - 地名などのコード記号で、鍵に値がないもの：Dordoigne、extremement（の extreme）。脱落の大半がこれ。
  - 形の近い記号の取り違え：ϖ の山2つ（il）と3つ（est）、# と横線つきの tt（les）、丸い ℒ（n）。
  - 鍵の値の違い：χ° は、ここでは pour と読むと合う（鍵では q）。横線つきの h は、ここでは tous（鍵では armée）。
  - 書き出しの3記号の読み違い（Nous）。
- この結果から、f. 218r の9・10行目で il と書いていた記号を tt（les）に直した（« pour veoir les ennemis »、« de les empescher »）。較正の6行そのものに合わせて鍵を直すことはしていない。
- 意味：書き起こしと鍵を合わせた読みは、文字で4分の1ほどの誤りを含みうる。ただし、この書簡では、文脈で記号の値を選んだので、較正の6行（文脈を使わずに読んだ）より誤りは少ないと見込まれる。これは確かめていない。

## 2回目の書き起こし（独立の読み、2026-10-20）
- 読み手：OpenAI の Codex CLI（ChatGPT アプリ同梱の codex-cli 0.163.0-alpha.10.2、既定のモデル。実行記録にモデル名は出ない）。
- 渡したもの：3ページの行画像（1行を左右2枚に分けたもの。f. 218r 27行・f. 218v 34行・f. 219r 19行。1回目と同じ傾き補正の画像から `second/crop_lines.py` で切り出した）と、依頼文（`second/PROMPT.md`）だけ。依頼文には記号の名前と形の説明だけを書き、値・1回目の書き起こし・鍵・解読文は含めなかった。値の分かる名前（=que、=pour、par2 など）は W01〜W18 などの中立の名前に置き換えた（対応は `second/names_map.tsv`）。
- 走らせ方：ページごとに1回、空のフォルダから `codex exec --ephemeral -s read-only` で別々に走らせた。実行記録（`second/codex_events_*.jsonl`）には、3回とも返答1件だけがあり、コマンドの実行やファイルの読み込みはない。出力は `second/transcription2_*.txt`（手を加えていない）。
- 1回目との突き合わせ（`src/compare2.py`。ページごとに記号の列の編集距離を取り、1回目の記号数で割った。区切りの `|` は除いた）：

| ページ | 記号（1回目／2回目） | 記号名の一致率 | 値の一致率 | 名前のずれを補正した後の記号名の一致率 |
|---|---|---|---|---|
| f. 218r | 713／710 | 76.7% | 77.4% | 84.2% |
| f. 218v | 927／934 | 63.2% | 65.6% | 85.0% |
| f. 219r | 499／507 | 61.5% | 63.9% | 76.8% |
| 計 | 2,139／2,151 | 67.3% | 69.1% | 82.8% |

- 食い違いの多くは、同じ形の記号に、2回目が別の名前を一貫して付けたものだった。2回目の名前ごとに、1回目で最も多く対応した名前を取ると（5回以上のもの）、13組になる：f→fi、fn→f、fi→dl、nu→dl、2→4、g2→J、phi→th、pl→zk、Ln→A<、.2.→.3.、sl→=la、co→en2、?→=que。文字で書いた形の説明だけでは、名前が形に結び付かなかったとみられる。f. 218v 6行目の左半分と5行目の右半分を画像で見て、δ 形（dl）・斜線つきの 4・ꝗ に続く形（J）を、2回目がそれぞれ fi・2・g2 と呼んでいることを確かめた。ほかの組は画像で確かめていない。右端の列は、この補正を2回目に当てた後の一致率で、補正を同じデータから決めているので、実際より高めに出る。
- 補正の後に残る食い違い（`second/diff_after_relabel.tsv`、283か所）のうち、値が変わる主なものは、4H（e）を 4（a）と読んだ18か所、fn を y2 と読んだ15か所、8（t）を dl（e）と読んだ11か所、2（m）を J と読んだ9か所。1回目は、似た形の記号を文脈で選んだ箇所がある（下の「限界」）。これらを画像で見直すことは、まだしていない（[OPEN.md](OPEN.md)）。
- 2回目の書き起こしを同じ鍵で解読して対照実験（各1000回）にかけると、本物の鍵の値は f. 218r −3.095、f. 218v −3.910、f. 219r −3.480 で、かき混ぜた鍵の最大（−3.952、−4.275、−4.360）を上回り、本物以上は3ページとも0／1000回だった。1回目（−2.35〜−2.59）より低いのは、上の名前のずれと誤読の分。
- 2回目の書き起こしを受けて、鍵と読みは変えていない（直した記号は0。食い違いはまだ画像で見直していないので、確かめたうえで直さなかった数もまだない）。

## AI の使用
- 画像の書き起こし、鍵の補い、解読、スクリプト、文書は、Anthropic の Claude（Claude Code、モデル Claude Opus 5.5）が行った。人（リポジトリの管理者）は、対象の選定、画像の保存、公開の判断をした。
- 1回目の記号名での書き起こしは、各行を1回読んだもの。多数決はしていない。別の AI（Codex）による2回目の書き起こしは上の節にある。
- **人は書き起こしを確かめていない。** 書き起こしは2回とも AI によるもので、AI どうしの一致は、人による確認の代わりにならない。
- f. 218v・f. 219r は、先に画像を見て平文を読み、その後で記号名に書き起こした。書き起こしが先の読みに引きずられている可能性がある。

## 限界
- 較正は6行（157記号）だけで、記号ごとの正確さ（書き起こしだけの誤り）は分けて測っていない。
- 似た形の記号（f／長い f／ƒ、δ／8／ɣ、ꝗ／4、鉤つきの ʃ の仲間、∝ と下に輪のある ∝、丸い ℒ と角ばった ∠）は、文脈で選んだ箇所がある。その分、対照実験は本物の鍵に有利になる。
- 推定した値（`inferred`）の多くは、この書簡の中の2〜3か所でしか確かめていない。1か所だけのものは `data/key.tsv` にそう書いた。
- 値が分からない記号と読めない箇所は [OPEN.md](OPEN.md) にある。
