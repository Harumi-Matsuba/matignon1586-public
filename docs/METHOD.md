## 手順
1. **画像**：Gallica の BnF fr. 15572（ark:/12148/btv1b9061879d）の225コマ（f. 218r）と226コマ（f. 218v–219r）。ページごとに傾きを補正し（f. 218r −3.5度、f. 218v −0.7度、f. 219r −2.6度）、行ごとに3つに分けて拡大した。画像はこのリポジトリに含めていない。
2. **書き起こし**：記号に名前を付け（`data/key.tsv` の1列目）、行ごとに記号名を並べた（`data/transcription_*.txt`）。原本の縦線（語の区切り）は `|` で残した。形に自信のない記号には `?` を付けた。
3. **鍵**：友清理士氏（Cryptiana）が復元した Mayenne–Forget の Cipher-2 の表を使った。表にない記号は、この書簡の中で複数の語に当てはまる値を探して補い、`inferred` として区別した。根拠の語は `data/key.tsv` の4列目にある。
4. **解読**：`src/decode.py` で鍵を書き起こしに当てた（`data/decoded_*.txt`）。読み（[READING.md](READING.md)）は、その出力に、語の区切りと句読点を補ったもの。

## 較正（当時の解読がある書簡での測定、2026-10-20）
- 対象：BnF fr. 15573 f. 103v（Mayenne から国王へ、1586年9月、同じ Cipher-2。Gallica ark:/12148/btv1b90618780 の212コマ）。左余白に当時の解読がある。
- 手順：暗号の1〜6行目（記号157個）を、当時の解読を見る前に、この書簡と同じ記号名・同じ鍵で書き起こした（`calib/transcription_f103v_l1-6.txt`）。左端に余白の解読の切れ端が写っていたが、読まないようにした。その後で、当時の解読（Brett Burford 氏の目読みによる文字を、212コマの画像で確かめたもの。« lad[icte] riviere » の略記だけ直した。`calib/ref_f103v_l1-6.txt`）と、文字の単位で突き合わせた（`src/calib.py`）。
- 結果：参照214文字に対し、編集距離54（置換21、脱落24、余分9）。**文字の一致率74.8%**（表の記号だけで71.0%）。
- 違いの中身（目で分類したもの）：
  - 地名などのコード記号で、鍵に値がないもの：Dordoigne、extremement（の extreme）。脱落の大半がこれ。
  - 形の近い記号の取り違え：ϖ の山2つ（il）と3つ（est）、# と横線つきの tt（les）、丸い ℒ（n）。
  - 鍵の値の違い：χ° は、ここでは pour と読むと合う（鍵では q）。横線つきの h は、ここでは tous（鍵では armée）。
  - 書き出しの3記号の読み違い（Nous）。
- この結果から、f. 218r の9・10行目で il と書いていた記号を tt（les）に直した（« pour veoir les ennemis »、« de les empescher »）。較正の6行そのものに合わせて鍵を直すことはしていない。
- 意味：書き起こしと鍵を合わせた読みは、文字で4分の1ほどの誤りを含みうる。ただし、この書簡では、文脈で記号の値を選んだので、較正の6行（文脈を使わずに読んだ）より誤りは少ないと見込まれる。これは確かめていない。

## 2回目の書き起こし（Codex、2026-10-20）
1回目の書き起こし（Claude）と比べるために、OpenAI の Codex CLI（ChatGPT アプリ同梱の codex-cli 0.163.0-alpha.10.2、既定のモデル。実行記録にモデル名は出ない）に、1回目・鍵・値を見せずに、行画像から記号名で書き起こさせた。4回走らせた。どの回も、ページごとに1回、`codex exec --ephemeral -s read-only` で別々に走らせ、依頼文は標準入力で渡した。値の分かる名前（=que、=pour、par2 など）は W01〜W18 などの中立の名前に置き換えた（`second/names_map.tsv`）。行画像は、1回目と同じ傾き補正の画像から `second/crop_lines.py` で、1行を左右2枚に切り出したもの（f. 218r 27行・f. 218v 34行・f. 219r 19行）。

| 回 | 置き場所 | 渡したもの | 実行記録 | 扱い |
|---|---|---|---|---|
| v1 | `second/v1/` | 依頼文（記号名と形の説明だけ） | シェルのコマンドなし。ただし、下の「画像の渡し方の不具合」がある | 見直しに使ったので照合の記録（独立とは呼ばない） |
| v2 | `second/v2/` | 依頼文＋記号の見本表（後述） | `ls ../img`・`rg --files ../img`（画像のファイル名の一覧）を実行 | 見直しに使ったので照合の記録 |
| v3 | `second/v3/` | v2 と同じ。見直しの後に、新しい文脈で | 3ページとも、入力のフォルダの `ls` を実行（中身は行画像・見本表・依頼文だけ。記録の中の作業フォルダのパスは `<scratch>` に置き換えた） | 独立の2回目 |
| v4 | `second/v4/` | v3 の依頼文に「コマンドを実行しない・ファイルを開かない」を足したもの。見直しの後に、新しい文脈で | コマンドもファイルの読み込みもない（3ページとも返答1件だけ） | 独立の2回目 |

- **記号の見本表**（v2〜v4）：友清氏の Cipher-2 の表の画像（README の「前提にしたもの」）から、記号の形だけを1つずつ切り出し、こちらの記号名を付けて並べ直したもの（65記号）。値の欄は入れず、並べ方も表の列（値）と関係のない順にした。表にない記号は、文字の説明だけ。見本表の画像はこのリポジトリに含めていない（画像を入れない規則のため）。依頼文は `second/v3/PROMPT.md`・`second/v4/PROMPT.md`。
- **画像の渡し方の不具合**：v1〜v3 では、行画像を `-i` で渡すつもりの引数が、シェル（zsh）で1つの長い文字列のまま渡り、Codex には「ファイル名が長すぎる」という形で届いていた。v4 で「ファイルを開かない」と指示したとき、Codex が画像を見られないと返して分かった。v1〜v3 では、Codex がエラーに出たパスから自分で画像を開いて読んだとみられる。画像を開く操作は実行記録に残らず、Codex のログ（~/.codex/logs_2.sqlite）にもこの実行の行はなかったので、何を開いたかは確かめられない。読めた範囲には、答え（1回目の書き起こし・鍵）は置いていなかった（v2 の `../img` は行画像だけ、v3 の入力フォルダは行画像・見本表・依頼文だけ）。v4 は引数を1枚ずつ分けて渡し直し、3ページの画像（見本表を含め 55・69・39 枚）が届いたことを、返答が全行の書き起こしになっていることで確かめた。
- 前の版（2026-10-20 のコミット 044cf00〜8e3a50b）の METHOD は、v1 について「行画像と依頼文だけを渡した」「コマンドの実行やファイルの読み込みはない」と書いていた。上の不具合のため、前者は正確ではなかった。

### 画像での見直し（f. 218v・f. 219r、2026-10-20）
v1 では、f. 218v・f. 219r の値の一致率が 70%（部分的な読みとして示す基準。下の「判定」）に届かなかったので、v1 との食い違い（名前のずれを補正した後の 193 か所。`second/v1/diff_after_relabel.tsv` は見直しの前の書き起こしに対するもの）と、その一覧の外で v1・v2 の読みと並べて気づいた4か所の、計197か所を、v2 の読みも並べて、行画像で1か所ずつ見直した。画像で確かめられたときだけ直した。

- **直した：19 か所**（f. 218v 14、f. 219r 5）。主なもの：区切りの前の x→r（f. 218v 1行目）、横線のある x を * や x から xs へ（3か所）、横線のない長い f を f から fi へ（2か所）、θ 形を a から th へ（f. 218v 22行目）、χ に小さな o の付く記号を =pour から xo へ（6か所）、f. 219r 13行目の抜けていた r を足す、f. 219r 18行目で画像に1つしかない記号を「r5 | s zk」から「zk?」へ。
- **直さなかった：178 か所**。画像が1回目の読みと合うか、画像では2つの形を見分けられなかったもの（4H と # と 4、fn と y2、2 と J など）。f. 219r 16行目の 4H?→# は、いったん直したが、ほかの 4H と # を見分けていないのに合わせて戻した。
- 一覧（箇所・1回目・v1・扱い・理由）は `second/review_f218v_f219r.tsv`。f. 218r は見直していない。
- xo（χ°）に直した6か所は、鍵では q になる。文脈ではどれも pour が合い、較正の行でも同じ形が pour の位置に出る（[OPEN.md](OPEN.md)）。読み（[READING.md](READING.md)）は pour のままにした。
- 上の見直しは、1回目を書き起こしたのと同じ読み手（Claude）が1人で行った。そこで、直した19か所を、別の2つのモデル（OpenAI Codex：codex-cli 0.163.0-alpha.10.2、既定のモデル／Claude Sonnet）に確かめ直させた。どちらにも、行画像・見本表・2つの読み（直す前と後。A・B の順は乱数）だけを渡し、値・鍵・読みは渡していない。結果は、2つがそろって直した後を選んだのが8か所、割れたか片方が「分からない」としたのが11か所、そろって直す前を選んだのは0か所（`second/recheck_f218v_f219r.tsv`）。そろって直す前を選んだ所はないので、19か所はどれも戻していない。割れた11か所のうち6か所は χ° の記号（=pour か xo か）で、Codex は直す前、Sonnet は直した後を選んだ。
- 注意：同じ確かめ方（2つのモデルがそろった所だけ直す）を、当時の解読がある fr. 15573 の5ページで、1回目と Codex の読みの食い違い297か所に試すと、そろって直した38か所のうち、当時の解読と合うようになったのは9か所、合わなくなったのは21か所だった。2つのモデルがそろっても、確かめとしては弱い。この19か所も、確かでないものとして扱う。

### 1回目との突き合わせ（`src/compare2.py`）
ページごとに記号の列の編集距離を取り、1回目の記号数で割った（区切りの `|` は除く）。「値の一致率」は、鍵で同じ値になる別名を同じとみなしたもの。「名前のずれを補正」は、2回目の名前ごとに、1回目で最も多く対応した名前に付け直したもの（同じデータから決めるので高めに出る。判定には使わない）。数字は、見直しの後の今の書き起こしに対するもの。

- 見直しの前の書き起こしに対する v1 の値は、f. 218r 77.4%・f. 218v 65.6%・f. 219r 63.9%（前の版の METHOD に書いた数字）。

### 判定
- 判定に使う値：独立の2回目（v3・v4）の、ページごとに低い方の値の一致率（`python3 src/compare2.py --judge`）。f. 218r 72.1%（v4）、f. 218v 82.5%（v4）、f. 219r 73.9%（v4）。
- 3ページとも 70% 以上なので、部分的な読みとして示す基準を満たす。全文の読みと呼ぶ基準（85% 以上）は、3ページとも満たさない。

## AI の使用
- 画像の書き起こし、鍵の補い、解読、スクリプト、文書は、Anthropic の Claude（Claude Code、モデル Claude Opus 5.5）が行った。人（リポジトリの管理者）は、対象の選定、画像の保存、公開の判断をした。
- 1回目の記号名での書き起こしは、各行を1回読んだもの。多数決はしていない。別の AI（Codex）による2回目の書き起こしは上の節にある。
- f. 218v・f. 219r の食い違いを画像で見直して直したのも Claude（Claude Opus 5.5）。
- **人は書き起こしを確かめていない。** 書き起こしは2回とも AI によるもので、AI どうしの一致は、人による確認の代わりにならない。
- f. 218v・f. 219r は、先に画像を見て平文を読み、その後で記号名に書き起こした。書き起こしが先の読みに引きずられている可能性がある。

## 限界
- 較正は6行（157記号）だけで、記号ごとの正確さ（書き起こしだけの誤り）は分けて測っていない。
- 似た形の記号（f／長い f／ƒ、δ／8／ɣ、ꝗ／4、鉤つきの ʃ の仲間、∝ と下に輪のある ∝、丸い ℒ と角ばった ∠）は、文脈で選んだ箇所がある。その分、対照実験は本物の鍵に有利になる。
- 推定した値（`inferred`）の多くは、この書簡の中の2〜3か所でしか確かめていない。1か所だけのものは `data/key.tsv` にそう書いた。
- 値が分からない記号と読めない箇所は [OPEN.md](OPEN.md) にある。
